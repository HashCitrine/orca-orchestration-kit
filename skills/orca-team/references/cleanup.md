# 완료 후 세션과 임시 워크트리 정리

기본값은 결과를 보존한 뒤 완료한 워커의 세션과 이번 작업용 임시 워크트리를 정리하는 것이다. 조정자가 정리를 책임진다. 스킬은 상시 정리 프로세스가 아니며 워커의 완료 보고만으로 물리 자원 회수가 증명되지는 않는다.

## 대상과 산출물 확인

- 시작 receipt에서 Dispatch, 실행 호스트, 세션과 새로 생성된 워크트리의 정확한 식별자를 기록한다. current나 기존 워크트리를 임시 생성 자원으로 취급하지 않는다.
- 현재 CLI의 `skills get orchestration`과 `skills get orca-cli`를 따르고, 회수가 불확실하면 `skills get orchestration --reference references/recovery-and-cleanup.md`를 읽는다. 명령과 플래그는 해당 CLI의 도움말로 확인한다.
- 완료 메시지와 실제 변경·검증 근거를 대조하고 필요한 결과를 조정자 작업 공간 또는 합의된 영구 위치에 통합·보존한다. 임시 워크트리 안의 파일 경로만 보고한 것은 보존 완료가 아니다. 미커밋 파일·추적되지 않는 산출물과 미통합 커밋도 확인한다.
- 성공·실패 여부와 별개로 settlement와 결과 보존을 확인한다. 실행 중, 무응답, 종료 미확인 상태를 완료로 간주해 정리하지 않는다. 기존에 남아 있는 다른 작업의 자원을 일괄 정리하지 않는다.

## 세션 회수

- 사용자 보존 요청이 없으면 `--keep-open`이나 `worker-keep-open`을 기본 적용하지 않는다. 사용자가 가져간 세션, 기존/재사용 세션, 소유권이 불확실한 세션은 임의로 닫지 않는다.
- 자동 회수 지원 런타임은 `worker-show`/`worker-list`의 `autoReleaseAt`과 `next`를 따른다. 예약은 회수 완료가 아니다. 즉시 회수나 워크트리 삭제 전 회수가 필요하면 `orchestration worker-release --dispatch <id>`를 사용한다. 보존 요청은 유지한다.
- receipt로 실제 released/already_released 여부를 확인한다. retained, release_pending, release_unknown을 회수 성공으로 보고하지 않는다. pending/unknown은 receipt의 복구 지시를 따르고 해결되지 않으면 보류 이유를 보고한다. 감독 중인 워커를 `terminal close`로 우회 정리하지 않는다.
- Orca가 보존한 출력 기록과 Task/Dispatch 이력은 유지한다. 조정 상태를 지우는 reset이나 세션 이력 삭제를 기본 정리로 사용하지 않는다.

## 임시 워크트리 제거

- 이번 작업에서 생성한 전용 임시 워크트리만 대상으로 한다. 조정자의 공간, 원래 존재하던 공간, 공유 공간, 사용자 보존 요청이 있는 공간은 제외한다.
- 해당 공간을 사용하는 모든 작업의 settlement와 세션 회수를 확인한다. 다른 세션·후속 작업이 사용하는지 Orca 조회로 확인하고, 소유권이나 종료 상태가 불확실하면 보존한다.
- Git 상태와 산출물 통합·보존을 확인한 뒤 `worktree rm --worktree <정확한 식별자> --json`을 사용한다. 삭제 대상의 실제 절대 경로와 식별자가 기록한 임시 공간과 일치하는지 확인한다. 원격 자원은 생성한 실행 호스트에서 처리한다.
- `--force`, `--delete-branch`, 실패한 hook 무시를 기본 적용하지 않는다. 삭제가 거부되면 원인을 보고하고 보존한다. 브랜치 삭제나 raw Git/파일시스템 삭제로 우회하지 않는다. 실제 반환 결과로 제거를 확인한다.
- 보고에는 회수한 세션, 제거한 임시 워크트리, 보존하거나 정리를 마치지 못한 대상과 이유를 포함한다. 정리 실패가 작업 산출물의 성공·실패를 바꾸지는 않는다.
