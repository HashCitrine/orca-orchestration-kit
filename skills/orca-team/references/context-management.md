# 조정자 체크포인트와 복원

## 위치와 책임

Run 생성 후 첫 배정 전에 조정자 작업 공간의 `.local/orca-team/runs/<run-id>/checkpoint.md`를 만든다. 실제 조정자 작업 공간을 확인하고 절대 경로를 기록한다. 작업자 임시 워크트리나 설치된 스킬 폴더에 저장하지 않는다. 이 파일은 실행 상태의 관찰 기록이며, Orca/Git의 실제 상태나 최신 사용자 지시를 대체하지 않는다.

기존 조정자만 갱신하며 작업자는 결과와 근거를 보고한다. 동일 조정자의 재연결과 다른 조정자로의 소유권 이전은 구분한다. 후자는 이 문서의 범위 밖이다. 런타임 기록은 staging·커밋 대상에서 제외한다. 이 저장소는 `.local/`을 무시하지만 다른 프로젝트에서도 그렇다고 가정하지 않는다. 다른 프로젝트의 Git 설정은 자동 변경하지 않는다. 인증정보·전체 대화·전체 로그를 복사하지 않는다.

압축 요약과 재개 안내에는 체크포인트의 절대 경로, 실행 호스트, Run ID를 남긴다. 같은 세션에서 이 정보가 유실되면 확인된 조정자 작업 공간의 해당 Run 경로를 찾는다. 여러 후보 중 현재 Run을 확정할 수 없으면 사용자에게 경로 또는 Run을 확인하고 임의로 선택하지 않는다. 새 세션에는 이 세 정보를 전달한다.

## 기록과 갱신

- 사용자 목표·제약·승인 범위나 주요 결정 변경 후, 메시지 처리 후, 대기·턴 종료 전에 변경 사항을 저장한다. 변경이 없으면 다시 쓰지 않는다.
- 배정·통합·정리 직전에는 대상과 의도를 pending으로 남기고 직후에는 receipt나 실제 Git 결과와 관찰 시각을 반영한다. 배정 전에는 Task/spec·실행 호스트·대상 공간을 기록하고, Dispatch 등 실행 후에만 알 수 있는 ID는 미확인으로 둔다. pending은 실행 성공이나 실패의 증거가 아니다.
- reply/ack에도 대상 메시지 ID와 처리 상태를 기록한다. 응답 전송 여부가 불확실하면 실제 메시지 이력을 확인한다. CLI가 요구하는 check/ack 절차를 파일 기록으로 대체하지 않는다.
- 같은 디렉토리의 임시 파일에 UTF-8로 완전히 작성하고 읽기 확인 후 교체한다. 쓰기 실패 시 마지막 유효본을 유지한다. 저장 실패 중에는 새 배정·통합·정리를 시작하지 않고 실패를 알린다. 복구 후 실제 상태부터 대조한다. 기록 전 이미 실행된 작업이 있을 수 있다.
- 실행·검증·통합·정리는 각각 기록하고 unknown을 허용한다. 검증에는 커밋/revision과 미커밋 변경 포함 여부를 적는다. 이후 변경되면 이전 검증을 현재 변경의 검증으로 간주하지 않는다.
- 본문에는 현재 진행·미해결 항목·다음 행동을 유지한다. 완료 작업의 긴 이력은 같은 Run 디렉토리의 근거 파일 등 영구 위치로 옮기고 짧은 결론과 경로만 남긴다. 미해결 질문·의존성은 제거하지 않는다. 상세 로그는 모순이나 근거 누락을 해결할 때 필요한 부분만 읽는다.
- 정리 전 산출물과 참조 근거(route JSON 포함)를 영구 위치로 보존하고 경로를 갱신한다. 체크포인트와 근거 파일은 워커 정리와 함께 지우지 않는다. [정리 절차](cleanup.md)를 따른다.

## 압축·중단 후 복원

1. 체크포인트와 최신 사용자 지시를 읽고 목표·제약·승인 범위·다음 행동을 확인한다. 파일이 없거나 손상되었으면 완료 상태를 추측하지 않는다. 손상 원본을 보존하고 Orca와 Git의 관찰로 재구성하며 확인할 수 없는 항목은 unknown으로 남긴다. 승인 범위 확인 전에는 그 승인에 의존하는 변경을 보류한다. 상향 이력을 확인할 수 없으면 0회로 취급하거나 추가 상향하지 않는다. 조회와 관찰은 계속할 수 있다.
2. 현재 CLI의 `skills get orchestration`과 `skills get orca-cli`에서 필요한 조회·복구 절차를 확인한다. 확인된 실행 호스트와 Run을 대상으로 작업·작업자·메시지를 조회한다. 여러 Run에서는 지원되는 명령에 대상 Run ID를 명시한다. `run-use`로 복원하지 않는다. 다른 Run의 메시지 수신에 영향을 줄 수 있다.
3. Task·Dispatch·세션·워크트리 식별자와 소유권, 미해결 질문 및 reply/ack 상태를 대조한다. 저장한 관찰보다 현재 Orca 상태를 우선한다. 조회로 확인한 실행은 조회 출처와 관찰 시각을 기록하며 유실된 시작 receipt를 얻은 것처럼 기록하지 않는다. 종료 미확인·무응답·receipt 유실만으로 작업자를 재배정하거나 회수하지 않는다. 실행 요청을 반복하기 전에 해당 CLI의 복구 가이드를 따른다. 사용자 보존 요청이 있으면 보존 대상과 자동 회수 예약 상태도 확인한다.
4. 통합 대상의 실제 Git 변경·커밋과 검증한 revision, 산출물·근거의 존재를 대조한다. 통합 pending이면 실제 변경을 먼저 확인하며 이미 반영된 변경을 다시 적용하지 않는다. 검증 근거가 없거나 현재 변경과 맞지 않으면 필요한 검증을 수행한다. 정리 pending/unknown은 실제 receipt·현재 자원 상태로 확인하고 성공으로 올려 적지 않는다.
5. 불일치를 해소하고 체크포인트를 갱신한 뒤 다음 행동을 수행한다. 이전 route JSON과 launch_args는 이력이다. 새 배정마다 기존 usage refresh·route·모델 검증 정책을 적용하며, 이전 Dispatch 종료 및 작업당 상향 이력을 보존한다.

새 세션은 위 절차로 상태를 읽을 수 있다. 기존 조정자의 소유권과 메시지 수신 연결을 현재 Orca 가이드로 확인하기 전에는 조회만 한다. 이 문서는 소유권 이전·자동 세션 교체를 구현하지 않는다. 확인되지 않은 경우 기존 조정자에서 재개하거나 사용자에게 연결 문제를 알린다.

Entire를 선택한 저장소에서는 [Entire 조회·보존 절차](entire.md)에 따라 아래 선택형 참조를 기록한다. Task 하나에 여러 세션·체크포인트가 연결될 수 있다. 먼저 운영 체크포인트와 실제 Orca/Git 상태를 확인하고, 판단 근거가 부족한 경우에만 필요한 Entire 기록을 조회한다. Entire 수집 상태를 실행·검증·통합·정리 상태와 합치지 않는다.

## 체크포인트 템플릿

아래 틀을 Run별로 복사한다. 미확인은 unknown, 해당 없음은 사유와 함께 기록한다. 실행/검증/통합/정리를 한 개의 done으로 합치지 않는다.

```markdown
# 조정자 체크포인트
- updated_at: <UTC ISO 시각>
- checkpoint: <이 파일의 절대 경로>
- host / project / coordinator_workspace: <실행 호스트 식별자 / 프로젝트 / 절대 경로>
- run_id / coordinator: <Run ID / 확인된 조정자 식별자>

## 목표와 운영 조건
- 목표 / 완료 기준:
- 최신 사용자 제약 / 승인 범위 / 보존 요청:
- 동시 작업자 수 / 상한·제약 / 선택 이유:
- 주요 결정과 이유:

## 진행 및 미해결 작업
### <Task ID 또는 배정 전 작업 이름>
- 목표 / 의존성 / 수정 소유권:
- host / Task / Dispatch / session / worktree ID·절대 경로:
- 공간 소유권: <이번 Run 전용 임시 / 기존 / 공유 / unknown>
- observed_at:
- 실행: <미배정 / pending / 실행 중 / 성공 / 실패 / unknown; receipt 위치>
- 검증: <미실시 / 성공 / 실패 / unknown; 명령·근거 경로·작업 공간·HEAD/revision·미커밋 변경 포함 여부와 변경 식별 근거>
- 통합: <미실시 / pending / 완료 / unknown; 대상 공간·커밋·변경 근거>
- 정리: <미실시 / pending / 완료 / 보존 / unknown; 세션 회수와 공간 제거 각각의 receipt·사유>
- 보존한 산출물·보고·route JSON / 상향 이력의 경로:

## 미해결 질문과 메시지
- message ID / 관련 Task·Dispatch / 질문·의존성:
- reply 상태 / 근거:
- ack 상태 / 근거:

## 실행 의도와 다음 행동
- pending 작업 / 정확한 대상 / 실행 전 상태 / 알려진 요청·작업 ID:
- 다음 행동 / 선행 확인 / 차단 사항:
- 완료 작업 요약 / 상세 근거 위치:

## Entire 참조 (선택한 저장소에서만, 관련 세션별로 반복)
- 관련 Task·Dispatch / 에이전트 / session ID:
- Entire 버전 / 실행 호스트 / 저장소·작업 공간 절대 경로:
- checkpoint ID 목록 / 연결된 commit·revision:
- observed_at / 수집 상태·실패 또는 누락 사유:
- 실제 조회 근거 위치 / 보존 위치 / 재조회 결과:
```
